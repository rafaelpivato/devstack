# DevStack v0.6 browser shell

- `npm ci`, `npm run typecheck`, `npm test`, `npm run build` (Node is a **development/CI-only** requirement).
- Source lives in `frontend/src/`. Compiled **versioned** assets and Vite `manifest.json` are tracked under `src/devstack/static/v06/`. CI rebuilds and rejects stale bundles; Flask and the Python wheel serve only these checked-in assets.
- Opt-in browser shell: `/__v06`. Deep links such as `/__v06/projects/<uuid>/repositories`, `/__v06/projects/<uuid>/services/<container-id>`, `/__v06/projects/<uuid>/jobs/<job-id>/logs` and `/__v06/runtime/operations/<uuid>` are allowlisted by Flask. Stable `/` and `/projects/<uuid>` remain the default existing UI until feature parity is complete.
- Project browsing still uses only existing `GET /api/v2/runtime`, `GET /api/v2/projects` and `GET /api/v2/projects/<uuid>`. I3 additionally exposes existing controller-owned `transition_submit/status/list` through strict Flask APIs. Project selection, GET/deep-link navigation, refresh and reconnect **never** trigger a transition; only explicit reviewed POST does.
- Root entry uses the **global active runtime**: active project → active project home; genuinely inactive → choose a project; transitioning, error, unavailable, or unknown → explicit status/error, never autoactivation. Inactive project inspection is safe and remains distinct.
- Hierarchical routes follow Project → Lane → Repository detail. The app uses native `history.pushState`, `popstate` and deliberate Back; a cold deep link uses the canonical parent. There is no synthetic global `current` UUID or browser-persisted active project, and no new routing dependency.
- I2 provides the hierarchical navigation shell; I3 adds guarded runtime transitions and receipts. I4 adds actual repository status, guarded single/bulk updates, repository-add receipts, branch preview/apply and imported-source selective review. Feature code is split into `features/repositories/RepositoryOverview`, `RepositoryOperations`, `RepositoryReviews` and shared components. The existing backend is authoritative for Git safety; repository mutations require global runtime inactivity, immutable head/revision checks and explicit user action.
- I5 adds actual controller-backed Compose services, log snapshots, verified private application links and supervised jobs. I6 adds project configuration (Compose revision, whole-collection revision-checked applications/tasks, webhooks, rename) and secondary Projects → Administration (GitHub public SSH identity and published-update guard). The old settings API remains intact; the new reviewed collection operation adds controller-side compare-and-swap under the global runtime lock.
- The stable installer/updater clones a GitHub release tag and runs `pip install`; it must **not** run Node, npm, or download browser dependencies on the host. Tracked build assets must be reproducible and included in the wheel/tag.
- Never put controller credentials, secrets, or private host paths into JavaScript bundles. Frontend calls only same-origin `/api/v2`; Flask retains CSRF/session, controller permissions, and typed IPC.
- Desktop responsiveness matters, but screen structure is mobile-first. I7 adds skip navigation, heading focus, 44px touch targets and constrained text wrapping. Status uses text and icons as well as accessible accents. Project create and GitHub import/receipt now live under Projects. Dependency audit is enforced by CI; the real iPhone and release-candidate acceptance checklist remains in `docs/v0.6-ux-parity-audit.md`.

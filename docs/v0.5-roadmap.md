# DevStack v0.5 implementation tracker

Target: **one configured project (or none)**, multiple Git repositories,
a single managed development runtime, direct Tailscale ports defined by
Compose, explicitly registered public webhook routes, and no execution
when inactive. Breaking reset: **no migration from v0.4**.

Architectural intent for v0.6: separate persistence/domain, application
services, HTTP/JSON API, and replaceable frontend assets. Backend must not
depend on Flask templates; do not invest in a disposable visual component
library in v0.5.

**Merge policy:** each branch starts from the latest `main`; wait for CI and
human review; no automatic merges. Keep package version `0.4.0` until PR 07
so the main-branch release workflow does not publish unfinished v0.5 work.

**Important release hazard:** the existing stable updater follows the latest
GitHub release. PR 06 must prevent old v0.4 installations from silently taking
a fresh-install-only v0.5 release. PR 07 must not merge until this is verified.

**PR 01 boundaries:** do not implement active/inactive runtime behavior here.
Existing Docker actions remain operational until PR 02/03 gate them. Legacy
project-named internals are temporary adapters to be removed in subsequent
PRs; public management URLs become single-project paths in PR 01.

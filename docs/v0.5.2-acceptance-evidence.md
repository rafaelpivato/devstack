## Remaining external release checks — do not certify prematurely

- **PENDING — real published-release clean-host installation:** `scripts/install.sh` deliberately fetches a published stable release and rejects v0.5.1. A complete fresh Ubuntu host installation with a real GitHub v0.5.2 release, Tailscale onboarding, project A/B configuration, A→B→A execution and a live manual release upgrade has **not** been executed on an externally provisioned VM yet. CI does verify wheel packaging, actual Ubuntu systemd units, local HTTP/IPC, Docker runtime and service restarts.
- **PENDING — private Tailscale device-to-service connectivity:** negative interface-binding safety is tested, but a second device connected to the same real tailnet hasn't yet verified a positive `http://100.x.y.z:PORT/` link on a host-bound Compose service.
- **PENDING — crash/reboot scenario on fresh host:** unit tests simulate controller crash/recovery and verify fail-closed reconciliation, while CI restarts the real controller in an inactive state; a physical/VM reboot during a transition must still be checked as final host validation.

## Release sign-off

Mark the release PR ready **only when** all automated checks on the final candidate pass and unresolved external checks above are either executed and recorded or are explicitly acknowledged in an amended acceptance decision. The release-publishing workflow must not bypass two-project Docker/systemd tests. No criteria may be declared green solely because this matrix lists a test name.

# v0.5.2 acceptance contract — multi-project / single-runtime

**Status:** Proposed (review together with [ADR-0001](adr/0001-multiple-projects-single-runtime.md)).  
**Purpose:** Prevent partial PRs and green single-project tests from masking violations of the product architecture.

## Release-blocking behavior (automated scenarios)

| ID | Requirement | Minimum executable proof | ADR rule |
|---|---|---|---|
| AC-01 | Register more than one project | Create/import Smoke A and independent Smoke B on one fresh instance, without deleting or replacing A; list both by stable ID | INV-01 |
| AC-02 | Persist independent configuration | Configure different Git repos, Compose, tasks, applications, secrets references in A/B; reopen UI and restart controller, verify both unchanged | INV-01, INV-09 |
| AC-03 | Select without activation | View B while A is active; no B containers, B commands or B webhook forwarding; A remains active | INV-02, INV-03 |
| AC-04 | Switch A -> B -> A | Start A, change/persist data in its named volume; switch B, verify A worker/containers gone; switch back A, verify data retained and B stopped | INV-02, INV-04, INV-09 |
| AC-05 | Concurrent activation | Race two activate/switch requests for A/B; at most one succeeds/admitted, never overlap owned workloads | INV-02, INV-05 |
| AC-06 | Deactivation failure | Make Docker cleanup fail or leave an unverified owned resource; runtime reports ERROR and refuses activation of B until cleanup is proven | INV-05, INV-07 |
| AC-07 | Generation-fenced jobs | Queue A job; stop/switch; reactivate A; delayed prior-generation worker cannot execute; new-generation worker can | INV-06 |
| AC-08 | In-flight work | Start long-running Compose exec, standalone image and webhook forwarding; switch while running; drain/cancel and verify stop before B starts | INV-02, INV-05, INV-06 |
| AC-09 | Startup/crash reconciliation | Kill controller mid-transition; restart controller / reboot host; fail closed until all DevStack-owned resources are reconciled; no auto-activation | INV-05, INV-07 |
| AC-10 | Project-aware routing | Unknown project ID fails; requests for B cannot mutate A, execute B while A active or expose A's private ports as B's | INV-02, INV-03, INV-08 |
| AC-11 | Webhook isolation | Register same route name under A/B; URL includes project ID; route only forwards for active identity and generation; inactive returns 503, unknown 404 | INV-02, INV-06, INV-08 |
| AC-12 | Filesystem and data safety | Switching retains working trees, edited Compose, task files, secrets and named volumes; only explicit deletion can remove them | INV-01, INV-09 |
| AC-13 | Separate privileges | Verify web service cannot open Docker socket or controller-owned secrets/database and cannot issue arbitrary Docker/host commands; allowed IPC operations work | INV-08 |
| AC-14 | Fresh host installation | Provision clean Ubuntu with systemd, Docker, controller and UI; configure at least two projects via private browser/API and complete A -> B -> A | INV-01, INV-02, INV-10 |
| AC-15 | Release/upgrade behavior | Old v0.5.1 schema is rejected rather than migrated or silently reused; new release checks daemon + registry + API and never auto-starts workloads | INV-07, INV-10 |
| AC-16 | GitHub import remains first-class | Import public Smoke Test via same project creation flow, then add another project from GitHub; preserve imported template path and source synchronization | INV-01, INV-03 |

## Test layers

- **Domain/unit:** registry validation, immutable identity, state machine and generation fencing; SQLite transactions and concurrency under independent Python processes.
- **Integration:** real Docker Compose stacks for **two distinct registered project IDs**; cross-project commands, cleanup, named volumes and webhook routing. Tests must assert actual ownership labels/resource state, not only API JSON.
- **Installation/system:** clean Ubuntu, systemd service privilege boundaries, private UI socket transport, daemon crash/reboot recovery and executable background jobs across browser disconnects.
- **Security negative cases:** wrong/unknown project ID, stale activation generation, unowned Docker container, controller unavailable, malformed imported manifest, symlink escapes, and invalid webhook destination.

## PR requirements

Each implementation PR should include a small traceability table:

| ADR invariant | Acceptance scenario | Implementation files | Test(s) | CI result |
|---|---|---|---|---|
| INV-xx | AC-xx | ... | ... | Pending / Passed |

A test marked `Pending` may be acceptable in an **unreleased integration branch** but not in the final merge to `main`. The release-publishing workflow must depend on the two-project Docker tests and fresh-host system checks; no unimplemented acceptance criterion may be waived by lowering the test coverage to only the original single-project Smoke Test.

**Release rule:** only publish v0.5.2 when AC-01 through AC-16 are green (or a deliberately changed requirement has its own approved superseding ADR). A documentation checklist is not a substitute for executing these tests.

# v0.5.2 Stage 5P — Manual DevStack updates

**Restores the owner-facing check/update control, not a second privileged
execution mechanism.** Only stable published releases from the installation's
configured GitHub repository can be installed.

- Dashboard → DevStack updates → Check for updates / Update now.
- Read-only JSON \`GET /api/v2/devstack/update-status?check=1\` shows installed,
  latest stable release and systemd update status.
- CSRF-protected \`POST /api/v2/devstack/update-now\` accepts **no** user tag,
  command or path. Refuses if any project is active or runtime is uncertain,
  or if a newer published release does not exist.
- Unprivileged web service creates only a mode-0600 marker in its mode-0700
  systemd RuntimeDirectory. A **root-owned path unit** consumes it and invokes
  the pre-existing independent \`devstack-update.service\`; browser/web process
  never executes systemctl or obtains Docker/root access.
- Root-owned standalone updater independently checks that the existing v2
  deployment is healthy and inactive before switching release pointers. It
  retains the atomic pointer swap, service restart verification and rollback.
- Status page can reconnect after the web service restarts; update requests
  are idempotent while a marker or updater run is already in progress.
- Periodic automatic update timer is unchanged.

Important: **this is not a "pull integration branch" button.** Developers
continue shipping reviewed feature branches via integration PRs. The installed
server updates only to completed stable GitHub releases; no arbitrary branch
or PR head can be installed through the browser.

# v0.5.2 Stage 3 — isolated runtime supervisor (integration only)

Implements the controller core described in
[ADR-0001](adr/0001-multiple-projects-single-runtime.md).
**Do not install on the existing v0.5.1 host**: the old Flask runtime,
Docker worker endpoints and installer still exist until later stages.

- `devstack.control.coordinator` owns one global runtime row,
  cross-process lock, UUID-based activation generation, and fail-closed
  A → B switching. It never infers the active project from the browser.
- `devstack.control.docker` uses an explicit Compose `-p devstack-<uuid>`
  and generation labels. Cleanup verifies owned containers are gone;
  it never deletes named volumes. Unknown managed resources block activation.
- `devstack.control.jobs` supervises saved tasks, Compose build/restart,
  cancellation and logs with last-moment admission under the coordinator
  lock. Standalone image tasks have explicit project/generation labels.
- `devstack.control.daemon` is a narrow Unix-socket, allowlisted JSON
  interface, run separately from Flask and the Docker-unprivileged web user.
  It reconciles actual containers on startup instead of resuming old work.
- `deploy/devstack-control.service` is a deployment **template**. Installer
  integration and verification of separate Linux accounts are later stages.

Running the new daemon in isolation (for controller development only):

```sh
devstack-control --state /absolute/private/state --socket /absolute/private/controller.sock
```

Requests must use the restricted local socket; it is not an HTTP endpoint.
Do not expose it on public/Tailscale ports or install alongside v0.5.1.
All input is fixed-operations only (no raw host command execution).

## Tests / release boundaries

- Tests in `tests/test_v052_control.py` validate A → B → A, concurrent
  activation, generation invalidation, failed cleanup, unknown resources,
  restart reconciliation, controlled jobs and socket commands.
- Docker CI additionally verifies the new controller against two real project
  stacks with independent IDs and preserved data, after retiring v0.5.1's
  pre-existing single-project smoke stack.
- Remaining: systemd accounts/installer cutover, source sync and project API,
  full webhook and UI integration, clean host/reboot acceptance suite.

**Passing Stage 3 alone does not complete AC-01 through AC-16.** No version
bump, no automatic merge to `main`, and no deployment until the complete
integration branch is ready.

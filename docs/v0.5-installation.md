# DevStack v0.5 — Ubuntu installation and automatic updates

**Release candidate:** PR 07 will publish v0.5.0 after merging into `main`
and successfully completing both the full Python unit test suite and Docker
integration checks. Run the installer only once the release is published.

## Installation

Install DevStack on a new Ubuntu 24.04 LTS (or another supported Ubuntu host
with Python 3.11+) running with root privileges. This is cloud-provider
independent: the code does not require AWS-specific services or credentials.

Once v0.5.0 is published, download and run the installer:

```bash
curl -fsSL https://raw.githubusercontent.com/rafaelpivato/devstack/main/scripts/install.sh | sudo bash
```

The installer fetches the latest stable GitHub release tag **once**, then
downloads its helper scripts/systemd units and installs its application from
that same tag. This only ensures a coherent initial installation; **it is
not a version lock**.

The built-in systemd updater remains enabled and checks for the latest
published stable version. New releases are installed automatically, including
v0.5.x, v0.6.x, and future versions. You don't need to reinstall the server
when the UI changes.

If the new release fails its health check, the updater restores the previous
release and records the failed tag instead of retrying it indefinitely. This
is a health-check rollback, not a database or data-model migration engine.

## What stays on the server

- `~devstack/.config/devstack/workspace.toml`: zero or one configured project.
- Git repositories, Compose configuration, registered apps, saved tasks,
  and other project files: persistent across DevStack application releases.
- Docker named volumes: retained when the managed development runtime is
  deactivated; existing Docker services are reconciled inactive at startup.
- Optional Tailscale private access and an explicitly enabled webhook Funnel.

v0.5 changes the workspace format compared with v0.4. For this transition
we'll use a freshly provisioned server and discard the old v0.4 machine;
**no v0.4 migration is being developed**. This is a one-time deployment
choice, not a policy restricting future releases.

v0.6 is planned as a backward-incompatible **frontend/UI redesign**,
reusing the v0.5 API and application/data model. It is not expected to
require rewriting `workspace.toml`, moving repositories, or recreating
the host.

If future versions do change persistent data, migrations can be added when
needed. Version-series restrictions are intentionally out of scope.

## Release verification

- Python unit tests, including automatic progression from v0.5 to v0.6.
- Bash syntax and portable Ubuntu installer checks.
- Build the packaged wheel; run the *installed* Gunicorn dashboard and verify
  `/healthz`, `/api/v1/dashboard`, and packaged CSS/JS assets.
- Exercise a real Docker Compose stack, active-only webhook forwarding,
  start/stop lifecycle, in-progress job cancellation, and named-volume
  preservation.
- Confirm release tags match the Python package version.
- After PR 07 publishes v0.5.0, validate on a real fresh Ubuntu server.

PR 07 sets the package version to `0.5.0`, and the GitHub publishing workflow
creates the stable release only after the verification jobs pass.

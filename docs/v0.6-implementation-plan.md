## Approved experience

1. Active project first: root lands on the one active project if any. No active project → explicit choose/activate flow; never autoactivate.
2. A persistent multi-project registry is secondary and inspectable. Selecting a project doesn't activate or switch it.
3. Hierarchical, back-oriented navigation. Project home → feature list → detail → logs/review as needed. No omnipresent jump-anywhere links.
4. Mobile-first with good desktop responsiveness; neutral dark theme with restrained accent, accessible labels/icons beyond color, compact layouts.
5. Work only with real v0.5.3 functionality. Existing APIs and security boundaries constrain screens; don't manufacture IDE, interactive terminal, PR editor, test-analytics, usage tracking, public API or GPT connection.
6. Keep a changeable shell, feature modules and reusable primitives. Screen layout/order/text can be refined PR by PR without rebuilding architecture.

Validate the exact `{action, project_id}` shape, action-target consistency, canonical UUIDv4 and 32-char lowercase hex idempotency header. ## I4 mobile repository workflows — PR #70

- Existing Flask HTTP/typed IPC paths are reused exactly: `repository_status/update`, `repository_add_submit/status`, `repository_bulk_submit/status`, `branch_preview/apply` and `source_review/apply`. No controller code or new arbitrary Git operation.
- Project → Repositories → Repository Detail, Add, Update-all, Branch Review, Source Review and durable operation detail. Strict deep-link allowlist; old `/` remains default.
- Read status shows actual branch, upstream, dirty, ahead/behind and HEAD. The targeted fast-forward operation passes inspected `expected_head`; the controller independently enforces clean origin tracking and inactive global runtime.
- Branch preview fetches Git refs on explicit user review, reports per-repository target, default fallback, dirty/blocked state, and immutable reviewed SHA-256 revision. Apply requires that revision; partial results never claim atomic rollback. Scope is one repository or all repositories.
- Source review displays the actual controller changes; selectable items can be selected, each locally modified item requires a separate overwrite checkbox, and apply carries the reviewed revision and exact selection/overwrite lists. Revision staleness fails closed.
- Add and bulk actions are controller-durable. Browser-generated 128-bit request key is saved before the POST, with same-key retry only on an explicit subsequent click, and receipt detail routes available after disconnect/reload. The browser does not auto-resubmit after losing a response.
- Inactive viewing is always read-only; controller is authoritative if the runtime changes between initial UI state and an attempted write.
- Feature screens split into reusable overview/detail, operations, reviewed operations and common components, so future mobile layouts can be rearranged without rewriting the transport layer.
- Frontend tests cover route hierarchy, runtime guard and exact JSON/idempotency headers; Python tests cover Flask CSRF and exact field shapes, no side effect on deep-link GETs. Existing Docker A→B→A and fresh Ubuntu security permission checks remain full merge gates.
- **CI/merge:** temporary asset bootstrap must be removed; final commit requires frontend typecheck/unit/bundle reproducibility/wheel, Python tests, Docker A→B→A and Ubuntu systemd/IPC checks. Record actual links/merge SHA after integration.
- **Follow-up security review:** npm CI currently reports dependency audit advisories in the preexisting locked toolchain. Review impact and remedy before the final v0.6 release gate; do not assume build-only dependency risk is acceptable merely because the deployed host runs no Node.

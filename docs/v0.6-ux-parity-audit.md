# DevStack v0.6 — I7 UX, parity and release-candidate audit

This is the **historical I7 acceptance record** from the v0.6.0 rollout; it does not claim current PR status. v0.6.0 and v0.6.1 have since been published. The default `/` UI still has no approved cutover to `/__v06`; unresolved manual acceptance remains open. See [v0.6.2 integration plan](v0.6.2-implementation-plan.md) and [issue #84](https://github.com/rafaelpivato/devstack/issues/84) for current work.

## Functional parity matrix

| Capability from v0.5.3 | New opt-in v0.6 route / flow | Boundary and verified design |
| --- | --- | --- |
| Active-project landing / inactive chooser | `/__v06`, Projects | Reads global controller runtime; project browsing never activates |
| Explicit runtime activate, switch, deactivate, reconcile | Project → runtime action; global runtime operations | Guarded controller receipt/idempotency; no browser auto-retry |
| Create empty project | Projects → Create | Inactive-project requirement; POST is not idempotent, uncertain outcome requires directory inspection |
| Import GitHub project | Projects → Import → durable receipt | Save 128-bit key before POST, same-key deliberate retry, no implicit activation |
| Register/review/fast-forward Git repositories | Project → Repositories | Status-backed HEAD checks; inactive controller gate, operation receipts |
| Batch update, branch preview/fallback, source review | Repositories → guarded review / results | Revision and per-item confirmation; no direct arbitrary git |
| Inspect Compose services / containers and logs | Project → Services → container snapshot | Controller-owned active project, bounded manual-refresh log output |
| Open registered applications | Project → Applications | Only links returned by verified active Tailscale port mapping |
| Task / Compose / ad-hoc supervised jobs | Project → Jobs → Run | Explicit acknowledgement and argv; no host shell/interactive terminal |
| Job detail / paged output / independently cancellable job | Jobs → Detail → Output | Persisted controller state, bounded offsets and cancel policy |
| Managed Compose YAML | Configuration → Compose | Controller-validated CAS revision and inactive runtime |
| Application/task definitions | Configuration → Applications & tasks | Whole-collection editor; atomic revision-checked save, not deceptive per-row edits |
| Webhook route configuration | Configuration → Webhooks | Existing independent ingress, scoped to registered project |
| Project display name | Configuration → Project name | Existing project rename endpoint |
| GitHub public SSH identity & authentication test | Projects → Administration → GitHub SSH | No private key revealed |
| Published DevStack release updater | Projects → Administration → Published updates | Only published release, independent inactive/restart guard |
| Legacy endpoints / CLI / one-active invariant | Old `/` and API remain during staging | Backend and default dashboard unchanged; owner review before cutover |

Not represented as parity requirements: generic shell, terminal/PTY, live Docker editing, PR editor, CPU graphs, automatic GitHub synchronization, GPT/MCP connectivity, usage tracking. These are not supported v0.5.3 controller features; future scope is separately scheduled.

# v0.5.2 Stage 5O — project-wide Git updates

Native, controller-owned, **background** safe fetch + fast-forward across all
registered repositories for exactly one project.

- One project action; each repository has a durable, independent status.
  Modified/untracked trees, detached HEAD, no origin upstream, diverged
  histories, and Git failures are skipped or reported. Safe repositories
  continue. **No reset, force checkout, merge commit, branch fallback,
  implicit template application, or automatic runtime activation.**
- Update uses the same per-repository checked fast-forward as v2's existing
  individual update, under the **global runtime transition/source-write lock**.
  Activating another project cannot interleave during a bulk operation.
- SQLite journal records progress after each repository; browser disconnect
  does not cancel work. Controller restart marks incomplete runs
  **interrupted** without re-fetching or trying to roll back successful refs.
- One batch globally at a time; retrying the same UUID-scoped request key
  returns the existing operation rather than repeating updates.
- Mobile page lists progress and final per-repository outcomes. History is
  recoverable through its operation ID.

API: POST /api/v2/projects/<project-uuid>/repositories/update-all
with 32-character hex Idempotency-Key and CSRF; GET
/api/v2/projects/<project-uuid>/repository-updates/<operation-uuid>.

Acceptance traceability: ADR INV-01/02/03/05/06/09,
AC-02/03/10/12/16. Tests: test_v052_bulk_repositories.py (real local Git),
plus existing Git, source-sync, Docker switching and Ubuntu privilege CI.

No v0.5.1 migration: integration-only SQLite schema v10. Still unreleased.

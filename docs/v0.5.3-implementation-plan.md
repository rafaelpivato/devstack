## Goal and version policy

Deliver native **`dev` over SSH**, as an unprivileged client of the existing typed Unix socket and controller, with mobile-width output. Build upon the real-host v0.5.2 deployment, which the owner reports can import two Smoke Test projects and switch A → B → A.

`v0.5.3` is a **provisional release label** for the current integration branch, not a promise to finish every milestone item in one release. Agree on a frozen *release subset* before updating `pyproject.toml` and creating release notes. If this grows, release a useful safe increment and continue remaining scope into v0.5.4 or later. A released tag is immutable.

No additional manual acceptance marathon is a prerequisite to starting work. However, deferred physical-host validations are **not** considered passed; confirmed failures require appropriate fixes and tests. See #50.

## Permanent invariants (not negotiable)

- Multiple independently persistent project configurations, **at most one globally active project runtime**.
- Selection is read-only/client-side, distinct from active execution.
- Global coordinator owns transitions and generation-fences all jobs, containers and webhooks. Fail closed.
- Privileged controller alone reads private state and operates Docker; web and SSH CLI only use typed allowlisted controller IPC.
- No second controller, arbitrary host command/shell bridge, public API, Docker group for CLI users, legacy v0.5.1 compatibility, or cloud vendor lock-in.
- The existing root-owned release updater is not replaced by a privileged CLI shortcut.

## Initial user-facing command map (proposed, refine with ADR)

| Goal | Command |
|---|---|
| Controller/global runtime | `dev status` |
| Projects | `dev project list` / `dev project show <uuid>` |
| Activation | `dev project activate <uuid>` / `dev project switch <uuid>` |
| Stop/recover | `dev project deactivate` / `dev runtime reconcile` |
| Services | `dev service list --project <uuid>` / `dev service logs …` |
| Tasks | `dev task run <name> --project <uuid>` |
| Jobs | `dev job list --project <uuid>`; `dev job logs <id> --follow`; `dev job cancel <id>` |
| Git | `dev project import …` / `dev repo status/update/branch …` |
| Machine-readable | `dev --json …` |

Short commands and mobile widths are a requirement, but CLI ergonomics may improve during review. No uncontrolled aliasing of active and selected projects.

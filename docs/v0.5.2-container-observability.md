# v0.5.2 Stage 5L — native Compose service observability

Controller-only, **read-only** inspection of the selected active project's
Docker Compose services and verified owned containers. This is not an app
proxy, advanced monitoring system, or a second runtime supervisor.

- `GET /api/v2/projects/<project-uuid>/services` returns configured
  Compose service names and their observed container state, optional
  Docker healthcheck status, container names and restart counts. An inactive
  project has `active=false` and an empty service list, **without consulting
  Docker**. A service missing a running container remains visible as
  `not-created`.
- `GET /api/v2/projects/<project-uuid>/services/<container-id>/logs?tail=150`
  returns recent text logs for a controller-verified container only (maximum
  200 lines requested, 64 KiB output, 12-second Docker read deadline).
- The mobile dashboard displays service status via a read-only API request
  and refresh button; a service log page can be revisited without any changes
  to Compose or container state.
- The controller verifies immutable project UUID, current runtime generation
  and Docker Compose ownership labels; rejects another project's containers,
  one-off job containers, unknown identities or ambiguous Docker metadata.
  Browser/API code has no direct Docker or host command access.
- Status and log reads are serialized with runtime transitions. Jobs, source
  sync and webhooks have unchanged lifecycle behavior.

ADR traceability: INV-02/03/05/06/08, AC-03/06/10/13; tests:
`test_v052_container_observability.py` plus real Docker smoke integration.

**Not included**: Tailscale private application links (separate frozen-scope
PR), metrics/alerting, reverse proxy, automatic Docker actions or public access.

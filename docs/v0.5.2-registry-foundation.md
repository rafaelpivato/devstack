# v0.5.2 Stage 1 — persistent multi-project registry

**Unreleased implementation, not a production upgrade.** This work is proposed for
`integration/v052-control-plane`, under
[ADR-0001](adr/0001-multiple-projects-single-runtime.md) and
[the 16-scenario acceptance contract](v0.5.2-acceptance-plan.md).

Stage 1 introduces `devstack.domain` and `devstack.storage`, independent of Flask
and Docker. It establishes:

- Immutable canonical UUIDv4 project and repository identities, separate from
  project slugs and display names.
- A standard-library SQLite registry that holds any number of projects and
  independently scoped repository metadata, with transactional writes.
- Explicit schema versioning without migration from the v0.5.1 TOML singleton.
- Validation and regression tests for duplicate slugs, project-scoped
  repositories, traversal attempts, unsafe database symlinks, concurrent writes,
  and unknown database schemas.
- No automatic activation and no destructive project deletion path.

**Scope boundary:** The old v0.5.1 API and controller are still in this
unreleased branch and do not yet use the new registry. This is deliberately a
foundation PR, *not* completion of AC-01/02. Filesystem workspaces, GitHub
onboarding, the separate controller daemon, SQLite runtime records, project
switching, job supervision, webhooks, and the v2 API are follow-up stages.
Do not tag or merge v0.5.2 into stable `main` until AC-01 through AC-16
have passed against two real independent Docker projects.

# DevStack v0.6.2 — historical stabilization integration plan

**Completed and published 2026-10-22.** This file captures the pre-release plan and is not a current merge blocker. The v0.6.4 root cutover is separately tracked in [#86](https://github.com/rafaelpivato/devstack/issues/86). Manual acceptance remains documented under #50.

Baseline: published v0.6.1, main `66605627785cbaad2a7ef336691951d19e7297a0`. Master tracker: [#84](https://github.com/rafaelpivato/devstack/issues/84).

## Invariants and release control
- Multiple persistent projects; at most one active runtime. Controller alone owns Docker and private project state.
- HTTP and SSH `dev` use exact-field guarded Unix IPC; no broad web privileges or arbitrary log/host command access.
- Stay Tailnet-private; read-only navigation/diagnostics never activates a project.
- Maintain legacy `/` and staged `/__v06` independently. No implicit cutover.
- This integration branch targets `main`; final PR is owner-reviewed and owner-merged. **No assistant merge into main, tag or publication.**

## Stages
1. **#82 navigation & #83 appearance foundation:** accessible 44px Administration cog on shared Shell; 320px/text-zoom testing; System/Light/Dark browser-local persistence, pre-paint theme initialization, semantic color tokens and deliberately contrasting code/log/form surfaces. Deuteranopia simulation and automated WCAG contrast/non-color-state checks.
2. **#80 runtime/updater diagnostics:** correlate restored request keys with authoritative controller transition receipts on mount and manual refresh; distinguish unknown/not found from terminal outcomes; require explicit same-key retry after authoritative preflight; safe copyable receipt fields, never raw request keys. Clearly separate read-only release checks from inactive-only installation and expose allowlisted updater phase, unit, result and exit status.
3. **#81 secure global diagnostics:** inspect persistent receipts, application logging, systemd unit and updater access boundaries first. Implement controller-owned, bounded, read-only allowlisted diagnostic events for runtime, controller, web and updater without forwarding arbitrary journald text or environment/credentials. Render per-source availability honestly, use 1/5/30 minute windows, one-tap copy and partial/truncated warnings. If genuine web/updater history requires design changes, document and add only the safe minimal collector within the existing processes/systemd units; never fake coverage.
4. **Parity/docs:** reconcile #50 and #51 independently, clean stale source documentation, bump Python version and author v0.6.2 notes; rebuild and commit deterministic Vite assets.
5. **Final CI and acceptance:** frontend locked install, full security audit, TypeScript, React tests, reproducible artifacts and wheel; Python unittest, Docker A→B→A; Ubuntu systemd/IPC/Tailscale security gates. Check all required results on integration current head SHA. Record any physical iPhone/host tests that remain owner-only rather than representing them as automated.

## Risk decisions
- Do not expose free-form system journals: regex-only redaction cannot promise privacy. Emit/retain a bounded allowlisted event schema at trustworthy process boundaries, provide freshness and source-availability metadata.
- Interrupted requests cannot be auto-replayed; if the controller knows no receipt, show uncertainty, not success/failure.
- Prior completed #79 fixes and #62 milestone are not new regressions. Preserve unresolved manual real-host evidence in #50 rather than auto-closing it.

Changes and verification evidence will be recorded in this file and the final PR as they land.

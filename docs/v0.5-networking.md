# v0.5 PR 04: private ports and webhook ingress

> Historical design (v0.5.x). Superseded in v0.7.3 by
> [ADR-0010](adr/0010-tailscale-public-private-ingress.md): private Serve
> HTTPS 8443 and shared public Funnel HTTPS 443 via `devstack-public`.

## Compose-owned development ports

DevStack does not assign, translate, or reserve development ports. Docker
Compose publishes them and Tailscale supplies private network access.

On the Ubuntu server, retrieve its current private IPv4 with
`tailscale ip -4`. Bind an application's published port **only** to that
address in your project's `.devstack/compose.yaml`. For example, replace
`100.101.102.103` with your server's actual tailnet address:

```yaml
services:
  api:
    build: ../api
    ports:
      - "100.101.102.103:8000:8000"
  frontend:
    build: ../frontend
    ports:
      - "100.101.102.103:5173:5173"
```

These are **examples from your services**, not DevStack fixed ports. For
imported templates, build paths remain relative to the source manifest
directory. Processes inside containers must listen on `0.0.0.0`.
Your tailnet ACLs/grants and host firewall must allow access. Avoid wildcard
host IPs like `0.0.0.0` because they can expose development services
outside Tailscale. Tailscale private TCP needs no additional Serve mapping.

`GET /api/v1/project/ports` reports actually published, running TCP
ports that are bound to the server's *exact* Tailscale IPv4. It never
exposes UDP bindings, wildcard/public listeners, or stale inactive links.
Registered app labels may optionally filter by container port; the source
of truth for host ports is always Compose.

## Explicit public webhook access

If separately enabled, Tailscale Funnel exposes HTTPS 8443 to a dedicated
loopback listener on 127.0.0.1:8767. The dashboard remains on a separate
tailnet-only HTTPS 443 Serve route.

Create routes in the private dashboard. Each is `POST /hooks/<name>`;
the one project name is never part of the public URL. An example URL is
`https://<your-node>.ts.net:8443/hooks/stripe`.

- Unknown paths/routes: **404** (GET for a valid route shape: **405**).
- Known route while INACTIVE, ACTIVATING, DEACTIVATING or ERROR: **503**
  with a retry hint. Never forward and never auto-activate. An ACTIVE\n  record persisted from a previous Linux boot is rejected before admission.
- Known route while ACTIVE: forward the untouched raw POST body and
  signature headers only to its allowlisted registered Compose app and
  exact configured path on the private Docker network.
- Forwarding holds a shared lifecycle lock. Deactivation acquires the
  exclusive lifecycle lock and cannot mark the runtime inactive until
  already-accepted forwarding calls have completed. Requests admitted
  after the deactivation state transition get 503.
- No redirects, generic ingress proxy, arbitrary destinations, new
  public ports, or automated firewall/Tailscale configuration.

Webhook app servers remain responsible for verifying the provider's
HMAC/signature/token. Upstream health errors return **502**. Body and
response sizes are capped.

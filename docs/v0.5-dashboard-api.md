# DevStack v0.5 — replaceable frontend architecture

PR 05 creates an architectural bridge between the v0.5 dashboard and the
planned breaking visual UX for v0.6. No framework or bundler is required.

## Boundaries

1. **Domain and infrastructure:** `workspace.py`, `runtime.py`, container
   and Compose adapters, Git, Tailscale, registries, tasks and webhooks. No
   dependency on Jinja templates or browser JavaScript.
2. **Application/view models:** `dashboard_state.overview(project)` produces
   the versioned, JSON-serializable v0.5 dashboard snapshot. One failing
   subsystem is reported under `errors` without hiding other data.
   Sensitive task arguments, runtime tokens and host boot IDs are excluded.
3. **HTTP adapter:** `web.py` exposes `GET /api/v1/dashboard` and
   `POST /api/v1/runtime/activate|deactivate` using the existing authenticated
   private dashboard and CSRF-protected session. Existing legacy form URLs
   are still supported for straightforward rollback/fallback.
4. **Replaceable presentation:** Jinja templates and static CSS, with small
   ES modules in `static/js`. `api.js` centralizes JSON requests and
   CSRF-aware actions. `polling.js` prevents overlapping requests and
   pauses updates when the mobile browser tab is hidden. Other modules only
   manipulate DOM and handle presentation.

## Stable JSON contract

`GET /api/v1/dashboard` returns a single object with:

- `schema_version: 1`
- `project: {name} | null`
- `runtime: {phase, project, updated_at?, message?}`
- `repositories: [{name, branch, dirty, error}]`
- `containers: [{name, service, state, health}]`
- `services: [{name, state}]` (Compose services, not systemd)
- `applications: [{name, service, container_port, state}]`
- `ports: [{service, container_port, host_port, url}]` (Tailscale only)
- `tasks: [{name, mode, service, image, network}]` (no command args)
- `recent_jobs: [{id, state, service, mode, started}]` (no command args)
- `compose_job: {id, action, state} | null`
- `webhooks: [{name, application, path, enabled}]`
- `errors: {section_name: human_readable_error}`

An unconfigured host has `project: null` and empty arrays. Inactive
projects never enumerate live Compose containers, service states or ports;
the registered metadata remains available. Errors are partial.

`POST /api/v1/runtime/activate` or `deactivate` requires
`X-CSRF-Token` from the dashboard's session-backed meta tag, returns
202 with `{ok: true, runtime: {...}}`, 403 when unauthorized by CSRF,
404 without a configured project, or 409 for lifecycle conflicts.
These endpoints call the same application service as the HTML fallback
forms. They must never bypass runtime admission checks.

## v0.6 migration

Replace the Jinja markup and CSS and reuse the versioned snapshot, runtime
use cases, API transport, polling utility and form validation. Evolve JSON
schemas by adding new `/api/v2` endpoints or backward-compatible fields,
not by making frontend components depend on Flask template internals.

**Out of scope:** introducing React, a build pipeline, recreating the
visual design, authentication overhaul, or adding unrelated application
infrastructure. Keep changes small and reversible. No new dependency.

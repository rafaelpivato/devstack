# v0.5.2 Stage 5N — Git branch switching

**Native v2 Git repository operations**, not the singleton Git runner.

- A project can preview switching all its registered repositories to a
  requested branch, or one repository by immutable UUID.
- Each repository fetches origin references, checks its current branch and
  dirty state, and obtains origin's **advertised HEAD** via
  `git ls-remote --symref origin HEAD` rather than guessing `main` or
  `master`. If the requested branch is absent, the verified origin default
  is selected explicitly and visibly in the review.
- Review identifies selected branches, fallbacks, blocked worktrees and the
  immutable reviewed revision. Apply refuses stale reviews and requires the
  project runtime to be **inactive and Docker-clean**.
- No `reset --hard`, force checkout, implicit working-tree discard, or
  blind project-wide rollback. Repo-specific success/failure is returned
  so partially completed runs can be inspected before a fresh review.
- Source `.devstack/` settings remain managed separately via the existing
  reviewed source-sync workflow; switching Git checkouts never applies
  templates, modifies Compose, or starts the project.

## Endpoints

`GET /api/v2/projects/<project-uuid>/git/branch-preview?branch=...&repository_id=...`

`POST /api/v2/projects/<project-uuid>/git/branch-apply`
with JSON `branch`, optional `repository_id` (null for all), and
`revision` from the preview. Browser forms provide the same two-step
workflow with CSRF validation.

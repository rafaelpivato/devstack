# DevStack v0.5.2 — Multi-project control plane

**Major breaking architectural release. Clean Ubuntu installation required.**
This version replaces the v0.5.1 single-workspace/singleton runtime with an
immutable-UUID project registry, a globally exclusive active runtime and a
private, mobile-first control plane. Existing v0.5.1 state is **not migrated**.
Preserve/back up important old repositories and volumes before decommissioning
the old server. Install v0.5.2 on a clean Ubuntu host.

## Highlights

- **Multiple durable independent projects**, with exactly one active
  Docker Compose/runtime project globally. Selecting a project is read-only;
  A → B → A transitions drain previous containers, commands and webhooks
  while preserving working trees and named volume data.
- **Concurrent indefinite commands** in the active project: isolated
  Compose `run` and standalone Docker image jobs, independent cancellation,
  background history and bounded logs that remain available after closing
  the browser. Saved Compose `exec` tasks remain supported with different
  cancellation guarantees.
- **GitHub projects and repositories:** import public HTTPS or private SSH,
  register multiple repositories within each project, inspect and
  fast-forward individually, or **Update all** with independent durable
  per-repository outcomes. Preview/confirm individual or project-wide branch
  switches; fall back to each repository's verified remote default if the
  requested branch is missing. Dirty/diverged trees are never force-reset.
- **Compose and application visibility:** service/container running state,
  configured Docker health checks, restart counts and bounded recent logs.
  Explicit TCP ports already published to the server's Tailscale IPv4 show
  direct private application links. No reverse proxy, public preview server,
  automatic Docker bind changes or open Internet endpoints.
- **Project configuration:** managed Compose/apps/tasks with reviewed
  selective source template synchronization and crash-safe journal/replay.
  Per-project webhooks are routed exclusively to the current active project.
- **Installer and security:** clean v2 controller and web systemd identities;
  only the controller may access Docker and private SQLite project state.
  Typed/allowlisted Unix IPC, CSRF-protected web actions, no arbitrary
  host command bridge.
- **DevStack updates:** latest stable GitHub release and installed version
  status; explicit **Update now** through private systemd marker to the
  existing root-owned atomic deployment/health/rollback updater. Periodic
  automatic release checks continue.

## Compatibility and operating model

- Only `devstack-control` and `devstack-web-v2` console entry points remain.
  Old `devstack.web`, `devstack.runtime`, singleton data and service units
  were intentionally deleted. An SSH command-line UI is deferred.
- Installer rejects an already populated legacy host and any latest stable
  release older than v0.5.2. There is **no in-place migration**.
- DevStack updates itself from **published stable tags**; the browser cannot
  install feature branches, integration heads, arbitrary tags, or execute
  root/Docker commands.
- Stop/deactivate the active project before applying a newer release.
  A successful update must leave the daemon healthy and runtime inactive;
  failed upgrades roll back the installed release pointer.

## Testing and release criteria

The full Python suite, real Docker A→B→A with project isolation/volume
retention/multiple concurrent jobs, and fresh Ubuntu systemd privilege
checks are required to pass as part of the release workflow.
See [ADR-0001](../adr/0001-multiple-projects-single-runtime.md),
[AC-01–AC-17 acceptance plan](../v0.5.2-acceptance-plan.md), and the
[acceptance evidence](../v0.5.2-acceptance-evidence.md).

Per [ADR-0002](../adr/0002-v052-release-gate-and-v053-validation.md),
**v0.5.2 is the first automated-test-verified deployable release**. Live
published-release clean-host installation, positive same-tailnet connection,
physical crash/reboot reconciliation and manual updater/rollback trial remain
**unexecuted and deferred to v0.5.3 operational validation**. Passing CI does
not certify those physical-host cases. Back up valuable project data before
using this initial release. The automatic workflow publishes only **after
human review and merge to `main`**, contingent on Docker/systemd and Python CI.

## Intentionally deferred

Native SSH/CLI support is targeted for **v0.5.3**, alongside deployment
validation, confirmed fixes and additional regression coverage. Interactive
TTY/browser shell, advanced monitoring/alerts, proxy/routing layer, external
GPT access, destructive Git repository management and rich application/task
CRUD forms remain deferred. Managed JSON editing remains available.

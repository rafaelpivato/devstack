# DevStack v0.7.2 — Actionable Tailscale Funnel setup errors

Field observation on deployed v0.7.1:
- `web-mcp-enable-requested` and `mcp-funnel-enable-requested` succeeded.
- `mcp-gateway-started` followed.
- `mcp-funnel-error-funnel-command-failed` occurred approximately 45 seconds later.

This matches the configured 45-second Tailscale subprocess timeout, though
the v0.7.1 implementation did not distinguish timeout from command rejection.

## Fix
- Classify Tailscale command timeouts separately from nonzero exit status.
- Interpret only **fixed, allowlisted patterns** from Tailscale stderr to
  surface permission, HTTPS, certificate and port-collision categories.
  Never expose raw command output, arbitrary host logs or credentials.
- Display actionable guidance and the Tailscale administration link inside
  DevStack's MCP screen. Ordinary troubleshooting and retry remain Web-only.
- Preserve the original failure code if gateway cleanup encounters a separate
  error. Funnel port 10000 remains isolated from private Serve 443 and
  optional webhook Funnel 8443.
- Add regression tests for timeout/error mapping and cleanup behavior.

## Acceptance

Automated CI verifies the classifier, existing MCP-to-controller connectivity,
frontend integrity, Docker smoke, and Linux systemd permissions. The actual
cause of the Tailscale failure and ability to establish a public Funnel still
require a real host test. Do not infer cloud ChatGPT connectivity from CI.

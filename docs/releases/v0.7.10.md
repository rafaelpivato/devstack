# DevStack v0.7.10 — full bounded diagnostics via MCP

The existing authenticated `devstack_diagnostics` tool now reports the
same **classes** of global diagnostic sources as the private dashboard:
controller, runtime transitions, Web events/storage status, updater unit
status/events, and MCP gateway/ingress events.

## Architecture

- The fixed-purpose **existing** root-owned MCP diagnostics timer (normally
  60-second cadence) captures only allowlisted Web event codes via **read-only**
  SQLite connections to the fixed Web-owned persistent and fallback stores.
  It also reads only the existing bounded `systemctl show` updater fields.
  It continues to capture sanitized MCP events from known units.
- The root collector writes one bounded JSON snapshot in the already-existing
  diagnostics snapshot path; the controller reads and validates the published
  schema. Public MCP continues to use **only controller Unix IPC**, never
  private Web HTTP, raw Web SQLite, journal access or Docker access.
- The private Web dashboard still reads its own live Web ring and updater
  properties, avoiding duplicated data from the controller's cached copy.
- Missing, invalid and stale collector snapshots produce explicit
  unavailable/partial source coverage; never `available` with a silently
  empty event list.
- MCP responses additionally include sanitized `web_storage` mode/error,
  `updater_status`, `partial`, `truncated`, and
  `support_captured_at` (Unix epoch milliseconds).

## Freshness and limits

Controller/runtime events are read live. Auxiliary Web/updater/MCP sources are
**near-live**: collected every 60 seconds and considered unavailable if the
snapshot is older than 150 seconds. Both dashboard and MCP support the same
1-, 5-, 30-minute windows and bounded event lists. An independent fresh
snapshot may omit a just-emitted Web event until the next timer tick.

The persistent Web store remains owned and inaccessible to the public MCP
gateway. No new service, public route, token scope, background telemetry,
systemd group or broad filesystem permission is introduced.

## Validation

- Python tests cover safe filtering and absence of secrets, volatile storage,
  source truncation, updater status and stale snapshot behavior.
- Ubuntu systemd integration checks the original Web-owned SQLite under
  actual Linux service identity and demonstrates the independent controller
  identity can read only the sanitized root snapshot, not raw Web state.
- Existing frontend, Docker and OAuth/IPC CI checks remain required.

## Acceptance after merge/release

1. Refresh Administration → DevStack diagnostics and confirm Web storage
   persistent with `web=available`.
2. In ChatGPT, call `devstack_diagnostics(minutes=5)` and check the Web,
   updater and MCP source coverage (the `support_captured_at` value shows
   data capture time).
3. If a source is partial/unavailable, inspect the provided safe error/state,
   not SSH or arbitrary host logs.

No changes to projects or MCP OAuth authorization. Release v0.7.10 is
published by the usual main-only release workflow after the owner merges PR.

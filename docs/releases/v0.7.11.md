# DevStack v0.7.11 — Web-first Funnel readiness and recovery (#101)

## Visible behavior

On a fresh or existing installation, Administration → ChatGPT / MCP now
shows the **local** Tailscale connection, pinned device identity, private Serve
route, requested public Funnel route, and loopback public-gateway HTTP health.
The existing Enable MCP / Refresh status workflow remains unchanged. Nothing
requires SSH. An already-working HTTPS :443 endpoint is not restarted or
reconfigured by these read-only checks.

On initial enable failure, the existing fixed-purpose privileged broker
classifies **verified** approval-required, policy-denied, certificate-pending,
certificate-error and unknown-timeout outcomes. The private dashboard offers
a Tailscale administration link only for relevant failures and a retry after
external approval. The application never follows arbitrary CLI-provided URLs
or auto-approves Funnel.

## Boundary and truthfulness

- Root-owned existing support timer captures only fixed read-only commands
  (`tailscale status --json`, `tailscale serve status --json`), the previously
  pinned identity comparison and `http://127.0.0.1:8768/healthz`.
- Outputs are fixed enumerations; no hostname, node ID, tailnet name,
  CLI stderr, request payload, secret, or raw route map is copied out.
- A published snapshot is validated and shared with the private dashboard
  and MCP `devstack_diagnostics` through the existing controller IPC.
- The checks do not test external TLS ingress from ChatGPT. The result
  explicitly says `external_reachability: not_tested`; successful
  server-side probes alone cannot prove off-tailnet public connectivity.
- No new services, proxies, roles, public routes or filesystem privileges.
  Private dashboard :8443 and public OAuth-protected MCP/webhooks :443
  remain unchanged. An unrecognized route is never reset or overwritten.

## Verification

Python unit tests cover new installs, connected/configured installs, disabled
MCP, wrong identity pin, webhook-preserving read-only checks, stale snapshots,
secret filtering, timeout/approval/policy/certificate classification. The
real Ubuntu systemd CI exercises the fail-safe preflight without requiring a
Tailscale account. All existing frontend, unit and Docker checks must pass.

After release, use Administration → ChatGPT / MCP and read the readiness
section; MCP `devstack_diagnostics(minutes=5)` returns the same
`network_preflight` field. If external ChatGPT access fails despite local
readiness, verify it from a genuinely separate network or via a successful
MCP tool call; don't mistake local readiness for end-to-end proof.

# DevStack v0.7.6 — Focused OAuth consent and project-scoped MCP reads

- Dedicated, minimal private :8443 OAuth consent page at `/connect/authorize`: DevStack identity, ChatGPT requesting client, broad access disclosure and Authorize / Deny only.
- Single-owner, all-or-nothing connection approval. No per-tool/project role grants or extra login.
- Nine read-only MCP tools: projects, runtime, project metadata, repository Git/sync status, Compose services, service logs, jobs, job logs, and bounded DevStack diagnostics.
- Every project-specific tool requires a canonical UUID and returns the verified project and source identity. Log reads additionally require a container/job ID, and responses are bounded.
- Existing Web :8765 -> controller IPC is the sole read bridge; public MCP still cannot open controller IPC, Docker, arbitrary host URLs or project filesystem.
- Existing `devstack_status`, `devstack_ping`, OAuth rotation/revocation and public webhooks remain independent.
- No service actions, Git synchronization side effects, command execution or activity analytics.

## Manual acceptance
Connect or reconnect ChatGPT; on an iPhone with Tailscale, approve from the dedicated consent page. Query projects, select one, list its services and logs, and verify the returned project/service identity. Revoke from Administration. Check private :8443 vs public :443 isolation, denied/expired authorization requests and controller health.

# DevStack v0.7.17 — explicit application URLs (no Docker discovery)

## Applications are bookmarks, not containers

DevStack now displays **explicitly declared HTTP(S) application URLs**.
A project may have multiple named applications that share a single Nginx
port and differ only in the URL path. Applications do not need to match
Compose services or Docker container ports, and do not require an active
Docker project to appear as links.

In the GitHub umbrella `.devstack/project.toml`:

```toml
[[applications]]
name = "Frontend"
url = "http://{host}:5173/a/login"

[[applications]]
name = "Django Admin"
url = "http://{host}:5173/b/admin/"
```

`{host}` is optional. When present, DevStack's Web UI substitutes the
hostname of the current dashboard connection (typically the workstation's
Tailscale MagicDNS name). Literal HTTP(S) URLs are also supported. A URL
must include its HTTP(S) scheme and host; path-only links would otherwise
target the DevStack dashboard's own port (8443) instead of the application.
DevStack validates URLs before persisting them and before rendering links.
The link is the user's explicit bookmark, **not a network/health guarantee**.
Users can open or copy the complete URL.

The existing Docker private-port diagnostic tool remains available to
inspect actual verified host mappings; it no longer generates application
links. The controller still passes its verified Tailscale IPv4 address as
`DEVSTACK_TAILSCALE_IPV4` into Docker Compose commands unchanged.

## Safe upgrade

The registry schema is upgraded transactionally from v12 to v13 by
adding a nullable URL column. Every old project and registration is
preserved. Legacy `name + service + port` definitions remain readable
for backwards compatibility, but **do not generate a guessed URL** and
are shown as needing an explicit URL. New application entries should
use `name + url` and never provide service/port.

Updating old applications to URLs is a separate, explicit source-review
operation after the corresponding umbrella GitHub changes are merged.
No migration automatically restarts containers, modifies project Compose,
or changes Tailscale Serve/Funnel settings.

## TrustedOutreach follow-up (after this release)

Keep a single existing Nginx HTTP entrypoint on host port 5173, routed
by paths `/a/`, `/b/` and `/c/`. Register `Frontend` at
`http://{host}:5173/a/login` and `Django Admin` at
`http://{host}:5173/b/admin/`, then drop the extra 5174 Nginx listener.
This follow-up belongs in the TrustedOutreach umbrella, **not** in
DevStack, and is not changed by this release.

No public port, proxy, container, OAuth permission or host networking
service is added. The standard verified wheel/updater path is unchanged.

## Verification

Release CI runs Python unit tests, frontend tests/type checks and Docker
smoke integration. New regression tests cover duplicate path bookmarks,
scheme/credential/placeholder rejection, persisted URLs, v12 migration,
and the continued diagnostic-only status of Docker port discovery.

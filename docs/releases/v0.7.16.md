# DevStack v0.7.16 — portable private application URLs over Tailscale

## What changed

DevStack now supplies a controller-verified Tailscale IPv4 address to managed
Docker Compose commands through the reserved `DEVSTACK_TAILSCALE_IPV4`
environment variable. This enables imported umbrella projects to define
portable private application port mappings without committing a specific
developer's machine IP to GitHub.

An application that explicitly opts in with a Compose mapping such as

```yaml
ports:
  - "${DEVSTACK_TAILSCALE_IPV4:-127.0.0.1}:5173:80"
```

can now publish only to the workstation's actual Tailscale interface.
DevStack's existing Applications view still reads verified, running Docker
mappings and never invents URLs. Without a verified tailnet address,
Compose fails closed to a loopback-only binding instead of using a
wildcard or public interface. A caller-provided value of the reserved
variable is overridden by the trusted controller.

This release includes the controller change merged in
[PR #123](https://github.com/rafaelpivato/devstack/pull/123).
It does not modify any imported project or enable port publishing by
itself; the project's own Compose configuration must explicitly opt in.

## TrustedOutreach rollout

The matching umbrella configuration is in
[TrustedOutreach PR #6](https://github.com/TrustedOutreach/trustedoutreach/pull/6).
It defines private Beacon and Django Admin application links using the
same existing Nginx service, without exposing Django, Conduit, Redis or
PostgreSQL directly.

1. Confirm the existing active TrustedOutreach project is ready for a
   brief maintenance window; DevStack's guarded updater does **not**
   replace its controller while a project is active.
2. **Deactivate** the project using DevStack Web or authorized MCP, then
   use the normal Web update path after this release is published.
3. Verify DevStack reports **v0.7.16** and the controller is healthy.
4. Fast-forward the imported TrustedOutreach umbrella checkout to its
   merged GitHub `main`. Review the source-configuration changes
   and apply only the intended Compose and application entries while
   the runtime is inactive. Do **not** reimport or edit the managed
   configuration directly.
5. Activate the same project, confirm six healthy containers, and use
   the Applications screen to verify/copy the two tailnet-only HTTP links:
   Beacon on host port **5173**, Django Admin on **5174**.
   The Django Admin listener redirects its root to `/b/admin/`.
6. If Tailscale is unavailable or Docker fails to bind the requested
   address, inspect the runtime transition receipt and diagnostics.
   Do not publish wildcard ports to work around a missing private link.

The Tailscale IP is resolved at Docker Compose execution time. A later
Tailscale address change requires recreating/re-activating the project to
update the running port bindings.

## Release verification

CI must pass Python unit tests, frontend integrity and the Docker
integration smoke tests, and the release workflow must publish a matching
signed/verified wheel with SHA256SUMS. The new controller tests cover
Compose validation, startup, cleanup, inherited variable override, and
loopback fallback; the existing exact-bind private-port checks remain
authoritative.

This is a standard verified-wheel upgrade from v0.7.15; no new
OAuth flow, additional daemon, reverse proxy or public Tailscale Funnel
route is required.

# DevStack v0.7.13 — Tailscale device naming (#104)

## Fresh installation

Set `DEVSTACK_TAILSCALE_HOSTNAME=my-devstack` alongside `DEVSTACK_TAILSCALE=1`
when running the regular installer. This optional setting applies at **first
Tailscale enrollment** for browser activation, interactive, and pre-provisioned
auth-key flows. Omitting it uses Tailscale's normal OS-based naming. A machine
name is a 1–63 character lowercase DNS label beginning with a letter; dots,
URLs, spaces, and shell syntax are rejected before authentication.

Do not rerun the fresh installer to rename an existing machine.

## Existing installation — Web-first

1. Open private DevStack HTTPS (Tailscale Serve :8443).
2. Go to **Administration → Network / Tailscale**.
3. Review the actual assigned FQDN and private/public links, enter the new
   machine name and explicitly acknowledge the external-link warning.
4. Request **Rename**, then watch the pending state and the last operation.
   The systemd path watcher invokes a narrowly scoped root action. No SSH,
   project deactivation or Docker restart is needed.
5. Copy the new private and public links when available. Update Safari
   bookmarks, registered GitHub/Twilio callback URLs and ChatGPT MCP connection
   settings as necessary. No third-party registrations are changed by DevStack.

The root worker rechecks the pinned Tailscale node ID and tailnet, and requires
the currently managed Serve/Funnel map before and after the rename. It runs
only `tailscale set --hostname=<validated-label>` with fixed argv and no shell.
The actual resulting `Self.DNSName` is authoritative: a tailnet name collision
may produce a suffix. The existing private :8443 and opt-in public :443
visibility/paths are not reset. A currently enabled public gateway has its
host configuration refreshed, without any project restart.

**Known limitations:** No public reachability / certificate readiness test is
performed as part of the rename; DNS and TLS propagation may be delayed. An
outside rename through Tailscale admin is reflected on subsequent live status
reads, subject to the existing node/tailnet pin. First-use browser activation
currently chooses the name from installer configuration rather than editing the
name inside the temporary approval portal. Returning to automatic naming is
not offered until its upstream semantics are proven. Unsafe unexpected
Serve/Funnel states fail closed instead of attempting to reset public routes.

**Diagnostics:** Administration → DevStack diagnostics (1/5/30 min), with
bounded `mcp-tailscale-rename-*` event codes from the systemd rename worker.
No raw CLI stderr, secrets, request arguments, or name values are logged.

## Testing

Unit regressions cover name/injection validation, stale tabs, root-only
handoff, identity checks, name collision suffixes, timeout and route safety.
CI should also run Python unit suite, frontend typecheck/build and Ubuntu
systemd smoke. A live rename and TLS propagation check remain owner-initiated
post-deployment steps.

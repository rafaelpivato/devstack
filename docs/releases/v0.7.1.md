# DevStack v0.7.1 — MCP request and Web diagnostics hotfix

This patch fixes the first live MCP enable test on v0.7.0: an attempt to enable
MCP returned `MCP request not queued: request_failed`, while the copied
5-minute diagnostic snapshot displayed `web=unavailable` and no events.

- Use the **existing verified Web systemd RuntimeDirectory** for the MCP
  request marker (`/run/devstack-update-request/mcp-action`), with a separate
  fixed-purpose path watcher. No arbitrary shell privileges; the updater's
  existing `trigger` is unchanged. The root release installer updates the
  MCP unit automatically when the owner installs this release through the UI.
- Expose read-only MCP request-queue readiness and precise allowlisted
  filesystem error codes (permissions, read-only mount, missing path, full disk)
  to the private Administration screen.
- Fall back to an ephemeral Web diagnostic ring in that same existing
  RuntimeDirectory if the persistent Web diagnostic state is unavailable;
  report `partial (volatile fallback)` rather than silently hiding errors.
  Existing 1/5/30-minute copyable snapshots include the safe MCP request
  failure events.
- Add real Ubuntu Web-user permission verification for the new marker location
  and unit tests for failed writes / Web event fallback.
- No remote funnel or MCP tooling changes and no additional privileged Web
  permissions. **No SSH is required to apply or test the hotfix.**

Upgrade using Administration → Published updates, then test
Administration → ChatGPT / MCP → Enable MCP. If another error occurs, copy
Administration → DevStack diagnostics and share the snapshot. Actual Tailscale
Funnel and cloud ChatGPT connectivity remain live acceptance tests.

# DevStack v0.6.4 — canonical mobile frontend and legacy cleanup

**Status: integration candidate for owner review; not yet merged, tagged, published or deployed.** v0.6.3 was not published; the owner explicitly chose v0.6.4 for this cleanup increment after v0.6.2.

## Functional changes

- Promote the v0.6 React project-first frontend from preview `/__v06` to the default `/`. The same stable UUID-scoped React routes now live directly at `/projects`, `/runtime`, `/imports`, and `/administration`. Saved preview URLs safely redirect to canonical paths after strict allowlist validation.
- Remove unused server-rendered Flask dashboard/form endpoints, Jinja templates, legacy static assets and UI-only helpers. Drop legacy fallback links from the React shell. **No legacy dashboard is kept under a new URL.**
- Keep the backend `/api/v2` contracts, controller-owned runtime authority, shared protected IPC, native `dev` CLI, private Tailnet boundary, root-owned updater, and immutable project IDs unchanged.
- Retain the existing `static/v06` **React build output** in the wheel to avoid an unrelated asset migration; its directory name is historical, not a second dashboard.
- Reconcile published v0.6.2 README/release documentation and historical tracking. Historical release notes remain available, and real-host acceptance #50 remains deferred rather than falsely marked passed.

## Update and rollback

The installer/updater continues to accept only published tags; production deployments remain on v0.6.2 until the owner squash-merges and main-only CI publishes this release. Users with a bookmarked `/__v06/...` path are redirected to the corresponding canonical route. Legacy `/projects/<id>/...` HTML form endpoints are intentionally removed; tools must use the existing `/api/v2` JSON contract or the `dev` CLI.

## Verification gate (pending)

- Full npm locked-install/security audit, TypeScript/React, reproducible generated bundle and packaged Python wheel.
- Python unittest and live Docker A→B→A plus fresh Ubuntu systemd/Unix socket privilege tests, all green on the same final integration head.
- iPhone Chrome/Safari root navigation, Back/deep refresh, System/Light/Dark contrast, copy/paste diagnostics; no controller mutation on GET, active-runtime update guard and real-server update/rollback to be confirmed separately.

## Deferred beyond this release

Automatic GitHub repository synchronization, per-project reaction policies (no-op/targeted restart/rebuild), hot reload, and external GPT/MCP access remain separate architectural work beyond v0.7. No new privileged endpoints or always-on service are introduced.

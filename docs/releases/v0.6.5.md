# DevStack v0.6.5 — compatibility bridge for CI-built wheel releases

**Transition release. Publish and upgrade to v0.6.5 before publishing v0.6.6.**

This release retains the compiled frontend assets in its Git source and provides a new, independently installed, artifact-aware updater. A v0.6.4 source-clone updater can still install this release. The new updater continues to install immutable legacy source tags through v0.6.5 for rollback and uses validated wheels for v0.6.6 onward.

## Mandatory migration checkpoint (root SSH operator)

1. Back up /var/lib/devstack and your application volumes. Deactivate the currently active project; check control/web health before updating.
2. Install the published bridge using the existing updater: `sudo python3 /usr/local/lib/devstack/updater.py --tag v0.6.5`.
3. Promote the trusted, tagged v0.6.5 standalone updater: `sudo /opt/devstack/current/venv/bin/python -m devstack.cli.install --refresh-updater`. This explicitly writes the root-owned updater outside the app tree, makes an atomic swap, and retains its pre-CLI backup.
4. Confirm the installed standalone updater has `verified_wheel`, that your native `dev status` works and that no project is active. Perform this on all supported hosts **before** publishing v0.6.6.
5. If an installation misses the bridge, the old updater will fail to install source-only v0.6.6 without changing the active release pointer. Pin `--tag v0.6.5`, recover the v0.6.5 source updater, and complete step 3 before retrying.

Do not reinstall DevStack or delete state to migrate. The existing /opt/devstack/current symlink, independent versioned venvs, rollback, controller privileges, IPC and CLI remain unchanged. Neither regular HTTP GETs nor the update-request marker automatically replaces a root-owned standalone updater.

## Trust and limitations

The new updater checks the published stable release, exact wheel/version identity, exact expected asset names, GitHub download URL, HTTPS redirects, release asset size and optional GitHub API SHA256 digest, SHA256SUMS, wheel metadata and referenced JS/CSS. The checksum is distributed with its wheel and **is not an independent signature or producer authentication**. GitHub repository controls, TLS and release immutability are part of the trust boundary; add/build-check GitHub Actions provenance attestation for v0.6.6 and plan a verifier-side provenance trust policy. Document GitHub immutability configuration before exposing v0.6.6 to automatic upgrades.

Physical-host smoke QA remains required: v0.6.4 → v0.6.5 bridge → v0.6.6 wheel, data preservation, project inactive guard, CLI, Tailscale, and rollback to prior known-good version.

# DevStack v0.7.9 — Persistent Web diagnostics (#100)

## Patch scope

- Repair upgraded installations whose original systemd Web unit predates the
  v0.6.2 `StateDirectory=devstack-web` setting. The verified release's
  root-owned post-install hook installs an idempotent, narrowly scoped systemd
  drop-in before the existing daemon-reload and Web service restart.
- Preserve `ProtectSystem=strict`, the unprivileged Web UID, and the existing
  separation from Docker and journal permissions. Do not create another daemon.
- Administration → DevStack diagnostics now reports the Web persistence mode
  and a bounded storage error category; no filesystem paths, raw exception
  messages, stack traces, credentials, or host output are disclosed.
- Keep the existing volatile SQLite fallback and explicit partial source
  coverage until persistent storage works. Any fallback events in the selected
  time window remain readable during recovery.

## Validation

- Python tests cover missing directory, ownership, permission, read-only,
  SQLite lock/corruption, unsafe paths, fallback behavior and no secret leakage.
- React snapshot-copy tests include persistence mode and safe reason.
- The fresh Ubuntu systemd job intentionally installs a **legacy Web unit
  without StateDirectory**, runs the same upgrade repair, then verifies
  persistent Web diagnostics across an actual sandboxed Gunicorn restart.
- Existing source-boundaries and release-artifact tests remain required.

## Operator acceptance

After the published v0.7.9 upgrade (no manual SSH), open Administration →
DevStack diagnostics and refresh. Expect `web=available`, persistent Web
storage, and no storage error. If the Web service is still partial, copy the
bounded snapshot and report the safe reason code with #100.

This is the patch already included in the review PR, not a separate
maintenance-release PR. It does not require MCP reauthorization or project
activation.

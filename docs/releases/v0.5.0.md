# DevStack v0.5.0 — Single-project runtime

**Clean install milestone.** v0.5.0 replaces the earlier multi-project design with a single managed development workspace. Provision a fresh Ubuntu server and retire the old v0.4 machine; no v0.4 data migration is provided.

## What's new

- **One project, multiple repositories.** A single `[project]` entry in `~/.config/devstack/workspace.toml` owns multiple Git checkouts.
- **Explicit ACTIVE/INACTIVE lifecycle.** Activation/deactivation, serialized transitions, recovery after daemon and host restarts, and fail-closed error reporting. Deactivation keeps project files and Docker named volumes.
- **Execution isolation.** Command workers, standalone Docker images, and Compose maintenance actions require an active runtime. In-progress managed work is stopped on deactivation; stale queued work does not restart.
- **Compose-owned networking.** Application ports are configured by Compose and only private TCP mappings bound to the host's exact Tailscale IP are shown. No fixed DevStack development ports or extra proxy.
- **Allowlisted public webhooks.** Optional Funnel ingress exposes `POST /hooks/<name>` only. Known routes return HTTP 503 while inactive; other paths return 404. Webhooks never activate the runtime.
- **Mobile-ready modular dashboard.** Project lifecycle, repositories, containers, services, ports, applications, tasks, jobs, and webhooks; framework-independent JSON view models and reusable `/api/v1` endpoints help prepare for the planned v0.6 UI redesign.
- **Portable Ubuntu installer.** Uses the latest GitHub stable release consistently for initial installation. The independent updater automatically follows **all future stable versions**, including v0.6, with health-check rollback on application startup failures.

## Installation on a new server

Once this release is published, review and execute the installer on a fresh Ubuntu 24.04 LTS instance:

```bash
curl -fsSL https://raw.githubusercontent.com/rafaelpivato/devstack/main/scripts/install.sh | sudo bash
```

The management app stays on localhost; configure private access with Tailscale Serve. Public webhook Funnel is separately opt-in. For cloud-init, use a trusted root-run Ubuntu user-data shell script.

See [installation and automatic updates](https://github.com/rafaelpivato/devstack/blob/main/docs/v0.5-installation.md) and the [v0.5 dashboard/API contract](https://github.com/rafaelpivato/devstack/blob/main/docs/v0.5-dashboard-api.md).

## Compatibility

This version **does not migrate existing v0.4 project configurations**. Replace the old host rather than upgrading it in place. For v0.6, the intentionally incompatible change is expected in the **visual user interface**; the workspace, repository folders, persistence and application/backend API are intended to remain compatible.

## Verification and release

Before GitHub publishes the tag, the release workflow requires both the full Python unit suite and real Docker smoke integration to pass. The smoke suite validates the packaged assets/Gunicorn service, Docker lifecycle and volume preservation, active-only webhook forwarding and background task cancellation.

A real Ubuntu VM installation is a post-release acceptance step; CI tests do not substitute for provisioning a complete new host.

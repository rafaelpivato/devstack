# DevStack v0.7.15 — MCP-native self-description for AI clients

## What changed

DevStack now explains its development workstation model to a newly connected
AI client without requiring ChatGPT account memory or project-specific custom
instructions. Its existing MCP server publishes standard
`initialize.instructions` with short operational guidance, and the existing
tool descriptions give actionable workflows even if an MCP client ignores
server-level instructions.

A client unfamiliar with DevStack can discover its projects and canonical
IDs, distinguish project registration from the globally active runtime,
import a GitHub umbrella repository containing `.devstack/` manifests, and
check durable operation receipts before claiming success. The new guidance
covers optional multi-repository GitHub manifests, Compose services and tasks,
safe preview/revision/expected-HEAD flows, and the difference between DevStack
workstation management and source-code editing in GitHub.

No extra MCP tools, service, daemon, credentials, OAuth scope, permission
or controller operation were introduced. Existing project registry, Docker
isolation and controller-owned authorization are unchanged.

## How to use

1. With DevStack MCP already connected and authorized, start a new AI chat
   with no prior DevStack memory or special ChatGPT Project instructions.
2. Ask the assistant to import a known GitHub umbrella repository. Supply
   an exact GitHub repository URL or give the assistant a separate GitHub
   connector able to resolve it; the DevStack MCP cannot discover unknown
   private GitHub repositories from nicknames alone.
3. The assistant should invoke `devstack_project_import`, verify its durable
   result via `devstack_project_import_status`, then inspect the imported
   project using its returned canonical ID. Import does not activate Docker.
4. If activation is separately requested, it should verify runtime state,
   invoke `devstack_transition` and inspect its completion receipt.

ChatGPT and other MCP clients may differ in how they use server
`initialize.instructions`; reinforced per-tool metadata is the
interoperability fallback.

## Verification

Existing HTTP MCP integration tests now verify the actual protocol
`Client.instructions` value and tool descriptions. Previous controller IPC,
status/ping and fixed tool-list expectations remain tested alongside
the normal Python unit tests, frontend integrity and Docker integration.

## Upgrade

This is a standard verified-wheel upgrade from v0.7.14. When the release is
published, use the ordinary DevStack Web updater/automatic update path.
The existing updater does not interrupt an active project runtime merely to
install this release. No OAuth reauthorization or host networking migration
is required.

# DevStack v0.5.3 — Native SSH CLI

**Release candidate (not published until final owner approval and main-branch CI).**
This patch adds the native `dev` SSH command to the already-published v0.5.2
multi-project controller. The web dashboard, private Tailscale model, and
single-active-runtime architecture remain supported; **no v0.5.1 migration**
or broad compatibility reset is introduced.

## What's new

- **One secure `dev` operator client.** Unprivileged Linux SSH users communicate
  over the same allowlisted Unix controller IPC used by the web UI. Operators
  must be explicitly enrolled into `devstackipc` (not Docker). Human-readable
  output fits narrow SSH/mobile terminals; `--json` supports scripting.
- **Project and global runtime controls.** List/inspect registered projects
  without activating them; explicitly activate, switch and deactivate by UUID.
  The existing exclusive coordinator, generation fencing, and fail-closed
  reconciliation are authoritative for both web and CLI.
- **Durable runtime transitions.** Controller-owned journal receipts support
  `--detach`, polling, status lookup and idempotency-key recovery after an SSH
  disconnect. Interrupted operations are recorded but never automatically
  replayed. A private sidecar journal keeps the v0.5.2 registry schema intact.
- **Services and saved tasks.** Inspect service/container health and bounded
  logs; read managed Compose; submit controller-owned Compose build/restart
  jobs and saved tasks. No raw Docker commands or CLI filesystem access.
- **Background disposable jobs.** Submit bounded Compose service/image argv,
  list/status jobs, paginate/follow bounded logs (NDJSON in JSON follow mode),
  and explicitly cancel independently cancellable jobs. Disconnecting a log
  follower does not stop the job.
- **Safe GitHub and Git workflows.** Import projects, add repositories,
  inspect/update a known HEAD, run durable bulk updates, and preview/apply
  branch changes using an explicit reviewed revision. All operations reuse
  the existing privileged controller checks and require project/repo identity.

See [native CLI guide](../native-cli.md) and
[ADR-0003](../adr/0003-native-cli-controller-ipc.md).

## Installation and upgrade

**For a new host:** use the documented trusted `scripts/install.sh` against
the latest **published** stable GitHub release. Its clean-host guard still
rejects v0.5.1/singleton state. The first install of v0.5.3 provisions the
versioned `/usr/local/bin/dev` symlink without auto-enrolling any human user.
For an explicitly trusted SSH operator, the root installer accepts
`DEVSTACK_CLI_OPERATOR=<linux-user>`.

**Existing published v0.5.2 server:** there is no need to reinstall or delete
projects. Once this version is published, deactivate the global project
runtime and use the dashboard's established stable-release updater. It
requires a healthy inactive controller; keep backups of valuable state.

**One-time operator setup after that first upgrade (required):**
The v0.5.2 installed **standalone updater does not refresh itself or create a
new CLI shortcut**, even though it can install the v0.5.3 application.
Connect as your trusted SSH account and run:

```sh
sudo /opt/devstack/current/venv/bin/python -m devstack.cli.install \
  --user "$USER" --refresh-updater
```

This root-only command creates `/usr/local/bin/dev` if the name is unused,
adds the explicitly named trusted user to `devstackipc` and replaces the
old standalone updater from the selected trusted release with an atomic
file update. The original updater is preserved once as
`/usr/local/lib/devstack/updater.py.pre-cli-backup`.
**Disconnect SSH and reconnect** for new Unix group membership, then run:

```sh
dev doctor
dev status
dev project list
```

The command refuses existing unrelated `dev` executables/symlinks; do not
blindly overwrite them. The release-owned binary remains available at
`/opt/devstack/current/venv/bin/dev`. Do not add the SSH user to the Docker
group. When rolling back to v0.5.2 the older release does **not** supply
the new CLI executable; the web/controller continue working and the shortcut
may be unavailable until upgrading again.

**Rollback:** The updater retains its atomic release-pointer and service
health/rollback behavior. The v0.5.2 registry version is deliberately not
migrated; the new transition receipts are kept in a separate private SQLite
sidecar. Retain backups and verify a real update/rollback on a disposable
host during first release adoption.

## Scope and limitations

- DevStack still supports **one globally active project**. Viewing a project,
  repository or job does not activate it.
- No interactive container shell, browser terminal, direct CLI Docker, public
  management API, cloud dependency or unconstrained host command bridge.
- SSH operators authorized for `devstackipc` have meaningful administrative
  capabilities through the controller; enroll only people you trust.
- Changing project source/Git branches requires an inactive runtime, clean
  worktrees and controller verification. Safe preview/apply operations do not
  silently discard local edits.
- The real v0.5.2 host has been manually installed and A→B→A switching was
  reported by the owner. **Real v0.5.3 deployment, rollback/reboot, durable
  data/volume retention and remaining #50 acceptance scenarios have not been
  manually verified**. Automated tests are not substitutes for these checks.
  Fix confirmed regressions in subsequent tested patch releases; do not
  mutate the immutable v0.5.3 release tag.

## Release verification

The candidate must pass the full Python unit suite, actual Docker A→B→A
smoke, fresh Ubuntu systemd web/controller separation and Unix IPC permissions,
and packaging/version matching. The final release is published **only after
the owner reviews and merges the integration PR into `main`**, followed by
the existing main-branch automated release workflow. No feature branch or
draft PR creates a release tag.

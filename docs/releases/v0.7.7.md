# DevStack v0.7.7 — Direct shared controller IPC and MCP operations

## Architecture
- MCP, Web and CLI independently connect to the same versioned Unix controller
  socket. Remove MCP's Web HTTP :8765 dependency, including status/diagnostics.
- The existing OAuth-protected public service is granted 'devstackipc' group
  membership; the Docker/host state privileges remain with the controller.
- No new controller, execution engine, per-tool authorization scopes, role
  management or approval UI. The existing private :8443 consent and public :443
  OAuth transport remain unchanged.

## New tools
- devstack_transition(action, project_id?, request_key?): durable activate,
  switch, deactivate, or reconcile (request_key can preserve retry idempotency).
- devstack_transition_status(operation_id): read the durable result.
- devstack_repository_check(project_id, repository_id): fetch remote status.
- devstack_repository_update(project_id, repository_id, expected_head):
  controller-fenced safe fast-forward; existing service reactions may execute.
- devstack_service_action(project_id, service, action): restart/redeploy one
  Compose service, returning controller job ID.
- devstack_task_run(project_id, task_name): run an already registered task.
- devstack_job(project_id, job_id): query owned job status.
- devstack_job_cancel(project_id, job_id): cancel an eligible independent job.

## Compatibility
- All previous read-only tools remain, with canonical project/source context.
- devstack_status now probes the controller over Unix IPC.
- devstack_diagnostics is controller-only. Its web/updater/mcp coverage is
  explicitly 'not_in_controller' instead of silently depending on private Web.
- No source changes, Compose restart, or project activation during upgrade.
- Owner should test v0.7.7 through ChatGPT before running any optional writes.

## Automated acceptance

- Wrong project/resource rejection and expected-HEAD handling.

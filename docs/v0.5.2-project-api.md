# v0.5.2 Stage 4 — project-scoped API and mobile UI

**Status:** Implemented on the unreleased `integration/v052-control-plane`
feature branch; deployment and final singleton removal remain Stage 5.

See [ADR-0001](adr/0001-multiple-projects-single-runtime.md) and
[acceptance contract](v0.5.2-acceptance-plan.md).

## Control boundary

The new `devstack.api.http:create_app()` Flask factory depends only on Flask
and `devstack.api.client`. It neither imports the controller daemon nor reads
SQLite/Compose files directly and has **no Docker permission**.

```text
Browser (project UUID in current tab's URL)
  -> Tailscale private HTTPS -> loopback Flask v2
  -> restricted Unix socket -> control daemon
  -> registry, coordinator and Docker
```

A project is **selected** by visiting `/projects/<uuid>`, with no state
change. Active project is reported independently by the controller's single
global runtime record. Multiple browser tabs can select different projects.
Only explicit button clicks/authorized POST actions activate or switch.

## V2 routes

| Method | Endpoint | Semantics |
|---|---|---|
| GET | `/api/v2/projects` | All registered projects |
| POST | `/api/v2/projects` | Create inert project |
| POST | `/api/v2/projects/import` | Import GitHub source without starting Docker |
| GET, PATCH | `/api/v2/projects/<uuid>` | Project detail / safe display-name edit |
| GET | `/api/v2/runtime` | One global runtime state (no secret generation) |
| POST | `/api/v2/projects/<uuid>/activate` | Activate only while globally inactive |
| POST | `/api/v2/runtime/switch` | Stop active project, verify, then start specified UUID |
| POST | `/api/v2/runtime/deactivate` | Stop runtime; preserve named volumes |
| POST | `/api/v2/runtime/reconcile` | Explicit fail-closed recovery |
| POST | `/api/v2/projects/<uuid>/tasks/<name>/run` | Execution requires active UUID |
| POST | `/api/v2/projects/<uuid>/compose/<action>` | Only build/restart via controller |
| GET | `/api/v2/projects/<uuid>/jobs/<job_id>` | Job must belong to requested UUID |

HTML forms offer equivalent actions with CSRF tokens and standard redirects,
including an always-visible **Use Smoke Test example** shortcut. The v2 app
intentionally contains no implicit single-project URL adapter and no v1 API
aliases. The old v0.5.1 Flask implementation remains only in the unreleased
integration branch for earlier CI and **must be removed in Stage 5**.

## Security, failures and limitations

- Session-cookie CSRF is required for all modifying browser and JSON requests;
  stable `DEVSTACK_SECRET_KEY` and private HTTPS must be configured by installer.
- Only explicitly allowlisted controller operations are forwarded. User input
  cannot provide arbitrary host commands, Docker CLI flags or file paths.
- Unregistered projects, invalid calls, conflicting runtime transitions and
  unavailable controller have separate HTTP errors; controller exceptions are
  reduced to public error codes without exposing internal paths or secrets.
- Inactive project application/task details are viewable; no inactive task can
  execute. Display name changes do not alter immutable project UUID.
- Full project settings editing, reviewed Git source sync, public webhooks and
  private networking UI will follow under subsequent v0.5.2 integration tasks.
  **Stage 4 does not claim the full v0.5.1 dashboard feature set has been ported.**
- Separate web systemd service and Linux user are provided as a **unit template**;
  the installer is not updated yet. No production v0.5.2 deployment.

## Verification

`tests/test_v052_api.py` uses the controller protocol and a fake Docker
backend to assert:
- Multiple registered projects / tabs, independent selected vs active project.
- Create/import while another project is active without interrupting execution.
- Inactive project read/rename but no runtime actions.
- CSRF protection for forms, JSON POST and PATCH.
- Controller outage returns 503 and fails closed.
- Project-scoped job ownership; no implicit v1 singleton routes.
- Actual Unix-domain socket/controller round trip, rather than only mocks.

The two-real-project Docker A→B→A and persistent PostgreSQL volume tests from
Stage 3 continue to run. Full release still requires all AC-01–AC-16 with a
clean Ubuntu systemd installation; do not merge unfinished integration code to
stable `main`.

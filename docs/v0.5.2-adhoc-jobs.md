# v0.5.2 Stage 5K — concurrent terminal-like commands

**Unreleased integration work**, governing ADR-0001 INV-11/12 and AC-17.

## User-facing concepts

- **Command:** a user-provided bounded argv array executed in a container.
- **Job:** internal persisted execution instance, with status, logs and cancellation.
- **Docker Compose service:** a project's long-running application infrastructure;
  not a special management mode for a command.

The controller accepts multiple concurrent jobs for the **same active project**
(up to 16 in-flight jobs as a conservative host protection limit). Commands
have **no default execution timeout** and continue when the dashboard or
browser disconnects. If ngrok exits, it stays exited; DevStack does not
auto-restart it. If the controller service or host restarts, the normal
reconciliation/cleanup policy applies, and no project autoactivates.

Commands are dispatched through disposable Docker containers, not the host.
Ad-hoc Compose commands use named and labeled `compose run --rm --no-deps -T`
containers; standalone image commands use equally labeled `docker run --rm`
containers. Each job owns a unique UUID and the current project generation.

**Independent cancellation:** cancellation marks the specific job
`cancelling`, terminates its attached client process, then verifies the
Docker container is owned by precisely that project/generation/job ID before
removing it. Other jobs and Compose services remain running. If ownership
or removal cannot be proven, fail closed into coordinator `error`.
Deactivation/switch still cancels all jobs and brings down the project's
Compose containers before activating another project.

Legacy saved **Compose exec** inside a shared service container remains
available for compatibility with project task definitions, but does **not**
offer unsafe single-process cancellation. It must be stopped by deactivating
the project. New ad-hoc commands use disposable containers for reliable
independent cancellation.

Compose `build` and `restart` are serialized exclusively against jobs,
because they mutate shared runtime infrastructure. Multiple regular
container commands do not block each other.

## Acceptance

AC-17 adds the workstation-equivalent workflow: start ngrok and Django tests
concurrently, close the browser, read independent logs, cancel only tests,
confirm ngrok and Compose services remain live, then deactivate/switch and
verify all work is drained and no stale-generation jobs can resume.

See `test_v052_adhoc_jobs.py`, the real Docker integration suite, and
ADR-0001. This does not claim the entire v0.5.2 release contract is met.

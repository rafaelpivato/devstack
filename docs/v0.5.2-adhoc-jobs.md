# v0.5.2 Stage 5J — native supervised ad-hoc container commands

**Unreleased integration change.** This extends the existing single global
v2 JobSupervisor; it does not reintroduce `command_runner.py`, old singleton
routes, host shell access, or a second execution admission mechanism.

## Features

- Ad-hoc commands accept a bounded JSON **argv array**, not raw host shell.
  Targets are precisely one service in the active project's Compose stack
  (`exec -T` or `run --rm --no-deps -T`), or one standalone image
  (`docker run --rm`) with the existing explicitly labeled generation and
  `none`/project network policy.
- The same global supervisor and immutable project UUID + generation fence
  that govern saved tasks govern these jobs. A single running/queued operation
  is admitted globally; a job cannot start after switching projects.
- Each project can view its latest 40 jobs, status and exit codes, and read
  log chunks from controller-owned, mode 0600 workspace files.
  Output is bounded to the first 2 MiB per job; further output is discarded
  by a draining reader so child processes cannot deadlock on a full pipe.
- Explicit job cancellation **deactivates the active project**, drains/terminates
  workers, stops all its managed Docker containers, verifies the global owned
  resource set is clear, and only then declares the job cancelled. This
  intentionally does **not** promise that killing the Docker CLI itself stops
  an `exec` process still running inside a container. If Docker ownership
  cannot be verified clean, the supervisor remains `error` and blocks all
  activation. Browser controls disclose the deactivation.
- Fetching history, status or logs of a different project is rejected.
  CSRF is required on ad-hoc submit and cancel. No freeform host argv, Docker
  socket operation or user-supplied workspace path is available.

## Endpoints

- `POST /api/v2/projects/<uuid>/adhoc` with fields
  `kind`, `service`, `image`, `network`, `command`.
- `GET /api/v2/projects/<uuid>/jobs`
- `GET /api/v2/projects/<uuid>/jobs/<job-uuid>`
- `GET /api/v2/projects/<uuid>/jobs/<job-uuid>/logs?offset=N`
- `POST /api/v2/projects/<uuid>/jobs/<job-uuid>/cancel`

## ADR acceptance traceability

- INV-02/03/06 → AC-03, AC-07, AC-08: global admission and generation fencing
- INV-05/07 → AC-06, AC-09: fail-closed cancellation and restart reconciliation
- INV-08/09 → AC-10, AC-12, AC-13: project-owned logs, allowlisted IPC, no
  implicit deletion/volume removal

Tests cover all modes, validation, concurrent admission, history isolation,
bounded log draining, cancellation and stop failure. The complete
AC-01–AC-16 clean-host release gate remains outstanding.
